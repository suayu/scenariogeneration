# RiskWeaver 多 Agent 阶段性实验报告

## 实验范围

本报告汇总三个独立冻结场景。四个模式使用相同场景、模型、攻击模式和下游安全验证器。由于百炼随后返回 HTTP 403，当前结果只用于判断是否值得继续投入，不构成有统计功效的论文结论。

## 四种模式

1. `single`：直接调用原规划函数，作为兼容基线。
2. `conditional_critic`：先运行基线；计划无效、历史缺失或存在多个候选时，再调用质疑 Agent。
3. `parallel_arbiter`：风险提案 Agent 与可行性提案 Agent 并行调用；只在通过原验证器的方案中进行确定性仲裁。
4. `parallel_memory`：在上一模式输入中加入冻结的、场景隔离的离线复盘记录。

## 回答四个问题

### 单 Agent 基线

三个场景均形成并执行了攻击，平均规划 5.72 秒，每次规划使用一次底层模型请求。它是当前覆盖率最高且成本最低的模式。

### 按需质疑是否值得

有效攻击覆盖率仍为 3/3，没有减少这个小样本中的无效计划。平均 D 从 0.0752 增至 0.0818，但规划时间增加 150%，请求数翻倍。现有证据不足以说明收益超过成本。

### 并行多样性是否提高覆盖率

两个并行提案把平均规划时间控制在 6.53 秒，但有效攻击覆盖率降至 2/3，平均有效 D 也低于基线。当前仲裁策略没有把提案多样性转化为更高覆盖率。

### 离线复盘是否减少重复失败

离线复盘模式只在 1/3 场景形成有效攻击，并有一次联合候选生成失败。历史经验在个别场景可支持有效方案，但当前检索与保守否决容易抑制可执行攻击，尚不能证明减少重复失败。

## 结论和下一步

当前结果支持保留四模式代码和审计数据，但不支持把多 Agent 作为论文主要贡献。若后续恢复免费模型额度，只需补充预注册的多场景对照；在此之前优先投入自车画像与针对性攻击实验。

所有模式的背景车间碰撞帧和背景车—静态障碍物碰撞帧均为零。该结果只证明已执行帧的离散 OBB 审计，没有连续时间无碰撞保证。
